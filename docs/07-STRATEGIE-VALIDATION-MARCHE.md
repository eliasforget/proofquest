# Stratégie de validation marché

## Hypothèse centrale

Les développeurs juniors veulent mieux comprendre et montrer leurs compétences réelles, et certains préféreront une expérience visuelle/gamifiée à un rapport classique.

## Tester avant de monétiser

### Test A — Désir
Publier une courte démonstration visuelle. Mesurer visites → clics "Analyze my GitHub".

### Test B — Activation
Mesurer clic → connexion → dépôt choisi → analyse terminée.

### Test C — Valeur
À la fin : "Quelle partie vous a réellement appris quelque chose ?" avec choix rapide.

### Test D — Partage
Mesurer le taux de copie du lien / partage. Le partage est un signal fort car il coûte une action sociale à l'utilisateur.

### Test E — Intention premium
Après plusieurs usages, afficher des fonctionnalités Pro futures avec un bouton **Notify me when Pro launches**, sans prétendre que le paiement est déjà disponible.

## Canaux organiques à tester

- démonstrations vidéo courtes ;
- posts techniques expliquant comment une preuve est détectée ;
- communautés de développeurs ;
- étudiants/alternants ;
- launch communities après stabilisation.

## Ne pas faire au départ

- achat de publicité avant d'avoir une activation correcte ;
- faux témoignages ;
- compteurs utilisateurs fictifs ;
- promesses d'emploi ;
- scores présentés comme mesure scientifique de la compétence.
